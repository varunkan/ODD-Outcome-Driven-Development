Spec Kit documents one process for building a feature or application (Spec-Driven Development) and another for diagnosing and repairing broken behavior (bug fixing); neither requires the other first. Use the process that fits the request below and invoke its skills yourself, one at a time and in this order, finishing each before you start the next.

Spec-Driven Development:
1. /speckit-constitution with principles that are already true for this repository
2. /speckit-specify with the request below as the feature description
3. /speckit-plan
4. /speckit-tasks
5. /speckit-implement
6. /speckit-converge; if it adds tasks, repeat /speckit-implement and /speckit-converge until it reports Converged

Bug fixing:
1. /speckit-bug-assess with the request below as the bug report
2. /speckit-bug-fix with the same slug
3. /speckit-bug-test with the same slug; if its verdict is failed, revisit the diagnosis or fix using that evidence, then test again
