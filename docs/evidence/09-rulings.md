# The rulings: every rule cluster, its verdict and its evidence

*Produced 2026-11-11 by a 31-agent run on Claude Fable 5.2: 15 validators ruled on every catalog item, a consolidator and a skeptic per area re-examined the rulings, then one agent each composed the method, the comparison, three independent critiques and the decision. Rendered from `data/validation/` by `tools/render_evidence.py`. The decision agent re-read only the draft audit; other figures are quoted from the earlier documents and were not re-checked in that step.*

Verdicts: KEEP (evidence it paid, or a cheap rule against a recorded incident class), REFINE (sound core, rewritten lean), MERGE (duplicate of another cluster), DROP (waste, ceremony, unmeasured with no incident, project-only, or contradicted by evidence). "Instructions" counts the catalog items the cluster covers; their ids are in `data/validation/areas.json` and resolve in `data/catalog/`.

### Dropped, and why

- **FR1-R4** Dropped: a fixed 200-line cap on every read window. Evidence: Tool outputs over 8 KB were ~0.55M tokens against 934.5M of context reads (FR-042); the guard refused a 221-line window in a working session (FR-121). Why: Drop stands: the measurement is against the lever, not for it. models.json RULE 6 lists 200-line windows as micro-management to retire.
- **FR1-R6** Dropped: target of 3 locator calls per file read and zero tool results over 8k tokens. Evidence: none Why: Drop stands: a ratio seen once, made a target, with no cost comparison; the 8k half is contradicted by FR-042.
- **FR1-R8** Dropped: capping worker steps at N tool calls and continuing in fresh steps. Evidence: Predicted 42% fewer reads from a replay. In practice the guard double-counted (median ratio 1.94 over 309 runners), cutting at 12-16 real calls; outcomes took 39-71 runner sessions and runners were 82% of 446M tokens, about 90M per outcome; no after-measurement (pos.json 'Step cap (#62)'). Why: Drop stands; I looked for a real-work payoff to restore it and found none. The only real data shows higher cost. pos.json calls it the largest recorded waste after the swarm.
- **FR1-R15** Dropped: standing instruction to delegate wide searches to subagents. Evidence: none Why: Drop stands: unmeasured here, and models.json RULE 12 says standing delegation lines raise cost on current models.
- **FR1-R16** Dropped: launch through a context-compression proxy. Evidence: none Why: Drop stands: a tool choice with an unverified ~50% claim; fails the project's own measure-or-revert directive.
- **FR1-R17** Dropped: compact context about every 1M cumulative tokens. Evidence: none Why: Drop stands: unmeasured and unenforceable by the items' own admission.
- **FR1-R19** Dropped: an LLM judge that watches every agent for token efficiency and turns each finding into a directive. Evidence: REQ-306 ran 14 hours with 81 agents and 23 REVISEs of 30, most naming no product defect; no saving attributed to efficiency judging is recorded (pos.json). Why: Drop stands: no measured payoff found to restore it, and it fed directive growth.
- **FR1-R25** Dropped: batch deletion regression legs once per device window. Evidence: none Why: Drop stands: POS-only, unmeasured, and overtaken by directive #66.

### Dropped, and why

- **PR-R26** Do not mandate a task DAG, node time caps or a checkbox format. Where a task list exists, a script may check that it has no cycles or orphan tasks. Evidence: none for benefit: all fifteen items unmeasured. Against: REQ-406's task list is 3,837 lines, REQ-323 carried about 340 tasks, and audit.json says at 30-second nodes the bookkeeping outweighs the code. Why: Overturned. The only incident is a bug in the validator, not a payoff from the rule; current models order multi-file work unprompted. It is the same ceremony PR-R39 drops.
- **PR-R31** Do not carry this product's concurrency and data-layer traps as method rules; keep them in the project's own on-demand checklist. Evidence: Each traces to one judge finding; no recurrence data. Why: Overturned. Project-specific content with no recurrence evidence; the reusable mechanism (dated, incident-linked, loaded on demand) is a learning-area rule (models.json RULE 10), not a project-management one.
- **PR-R38** Do not build a fixed relay of role agents, several teams, or a fixed stage sequence with a judge on every stage, and do not measure success by busy seats. Start with one team on one outcome. Evidence: REQ-306's swarm: 14 hours, 81 agents, 23 REVISEs in 30 verdicts, 13 serial spec and design rounds in 190 minutes; outcome-first reached a host proof in about 2 hours (pos.json). Why: Stands. No measured payoff found for any of the thirty statements; the measured evidence is all against.
- **PR-R39** Do not impose planning ceremony: mandated task DAGs, 30-second task caps, large checkbox ledgers with ticking tools, mirrored checklists, required headers or a toolkit pass per stage. Require only what a check reads: outcome, proof and tree. Evidence: 255 of 340 boxes open after an outcome run while earlier work sat done but unticked (task_evidence.py:1-14 per the ruling); process markdown 43.1 MB against 7.7 MB of product Dart (METHOD-MEASUREMENT.md per the ruling). Why: Stands and now also covers PR-R26. No measured benefit found for any item.
- **PR-R40** Do not carry one product's architecture decisions, lock-script bug fixes or workflow-runtime quirks as method rules. Fix them in the code with a regression test and record the architecture in the project's design file. Evidence: A released lock left as a file blocked the merge door for 35 minutes, twice (per the ruling). The incidents are bugs, not method. Why: Stands. Nothing here paid as a method rule.
